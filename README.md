# Network Traffic Analyzer

A Python tool that reads a packet capture (`.pcap`), summarizes the traffic, and flags common suspicious behavior: port scans, ping sweeps, DNS tunneling, large uploads to external hosts, and use of cleartext protocols. Packet parsing uses [Scapy](https://scapy.net/); the detection logic works on plain Python records, so it is easy to test without a capture file.

## What it reports

**Traffic summary:** protocol mix, top talkers by bytes sent, top destination ports, and a unidirectional flow table (`netanalyzer.summary.flows`).

**Detections:**

| Rule | Logic | MITRE ATT&CK |
|---|---|---|
| `port_scan` | One source sends bare SYN packets to 20+ distinct ports on one host within 60 s | T1046 |
| `ping_sweep` | One source sends ICMP echo requests to 15+ distinct hosts within 60 s | T1018 |
| `dns_tunneling` | 10+ queries with long (20+ characters), high-entropy (Shannon entropy 3.4+) subdomains under one parent domain | T1071.004 |
| `large_upload` | 500 KB+ sent from an internal (RFC 1918) host to one external host | T1041 |
| `cleartext_protocol` | Internal host opening FTP, Telnet, TFTP, POP3, or IMAP connections (informational) | T1040 |

All thresholds are function parameters in `netanalyzer/detections.py`.

## Usage

```bash
pip install -r requirements.txt
python scripts/generate_pcap.py                 # creates data/sample.pcap (about 1,750 packets)
python -m netanalyzer data/sample.pcap
python -m netanalyzer data/sample.pcap --format json --out findings.json
```

Sample output on the generated capture:

```
| Severity | Rule               | Source        | Detail                                              |
| high     | port_scan          | 203.0.113.66  | SYNs to 200 distinct ports on 10.0.0.5 within 60s   |
| high     | dns_tunneling      | 10.0.0.25     | 40 long, high-entropy queries under example-bad.test |
| medium   | large_upload       | 10.0.0.31     | 0.93 MB sent to external host 198.51.100.200        |
| medium   | ping_sweep         | 203.0.113.67  | ICMP echo requests to 60 distinct hosts within 60s  |
| info     | cleartext_protocol | 10.0.0.40     | 1 Telnet connection attempt(s)                      |
```

## Tests

```bash
pytest -q
```

10 tests cover entropy, the internal-address check, each detection (including negative cases: slow scans, ICMP replies, normal DNS names, inbound traffic), the summary statistics, and an end-to-end run against the generated capture that also checks normal clients produce no findings.

## Design notes

- **Internal vs external addresses** use an explicit RFC 1918 check. Python's `ipaddress.is_private` also returns true for documentation, loopback, and link-local ranges, which made the synthetic "external" hosts look internal. A test now guards against that.
- The cleartext rule only counts connections opened by internal hosts, so inbound scans that happen to probe port 23 are not reported as cleartext use.
- Scan detection uses a sliding window over (time, port) pairs, so a slow scan spread over hours is not flagged. That is a known blind spot.

## Limitations

- **The sample capture is synthetic**, generated by `scripts/generate_pcap.py` with a fixed seed (internal hosts in 10.0.0.0/24, external hosts in the RFC 5737 documentation ranges). It contains no real traffic.
- IPv4 only; IPv6 packets are skipped. Detection is threshold-based and will miss low-and-slow activity and can produce false positives (for example, a legitimate vulnerability scanner).
- Built with AI assistance (Claude); I reviewed and ran all of the code.
